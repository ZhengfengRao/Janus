# Janus 产品体验规格：交互、状态与文案

## 0. 本文定位 / 与其他文档关系

本文是 Janus 的**交互、状态与文案规格**，负责把 Janus 的受托行动产品模型落到用户可感知的入口、界面状态、控制动作、授权缝、风险预算、复盘证据和文案模板。

本文拥有：

```text
- Janus Entry / Janus 入口的行为规格；
- Janus Surface / Janus 主行动面的生命周期状态 UX；
- Delegation Center / 受托关系中心的长期治理行为；
- 自主等级、standing authorization 与 risk budget 的体验表达；
- 关键 UI 状态规格；
- 交互文案与信任表达模板；
- 代表性用户旅程与场景矩阵。
```

本文不拥有：

```text
- Janus 的完整产品哲学；
- 完整产品验证框架；
- runtime 架构、执行引擎、权限系统实现；
- MVP PRD、商业化方案、插件生态或开发计划。
```

本文继承但不重复展开的核心边界：Janus 是 **full-capability entrusted Agent / 全能受托 Agent**。它承担软件世界中的跨 App 数字行动，在授权范围和风险预算内自主完成任务；当行动需要新的判断、身份承担、责任确认，或超出授权 / 风险预算时升级确认。当前上下文是线索，不是任务边界；一次确认不等于长期授权；记忆必须被治理，不得静默沉淀。

## 1. 产品空间：三种界面，只做三件事

Janus 的体验空间只有三种核心 Surface：

```text
Janus Entry       / 发起、召回、轻状态、停止/接管入口
Janus Surface     / 一次受托任务的生命周期协作界面
Delegation Center / 跨任务授权、风险预算、记忆、任务账本与信任恢复治理
```

### 1.1 Janus Entry / Janus 入口

**职责**：从任意 App、任意对象、任意工作现场发起一次受托任务，并在任务期间提供最低限度的状态与控制锚点。

**必须支持**：

```text
- 快捷键入口：输入要完成的目标，不是搜索关键词；
- 对象入口：选中文件、文本、网页、联系人或窗口后发起；
- 胶囊入口：常驻轻量入口，任务中变成状态与控制锚点；
- 恢复入口：召回等待确认、安全停下、用户接管或最近任务。
```

**必须体现**：按住 Janus Entry 或语音按钮开始捕获，松开提交；取消手势不创建 Task。长按语音的高频路径应是：

```text
按住说出目标 → 松开提交 → Janus Surface 展开 → 授权覆盖的任务直接执行 / 完成 / 升级确认
```

**不得承载**：完整任务解释、长期治理、跨任务权限管理、完整审计历史或任务期间的新任务输入中心。

### 1.2 Janus Surface / Janus 主行动面

**职责**：承载一次受托任务从理解到复盘的完整生命周期。Janus Surface 不是普通侧边栏，也不是一组分离面板，而是同一受托行动界面在不同状态中的连续形态。

**生命周期**：

```text
Intent Capture
→ Understanding
→ Plan / Action Trace
→ Autonomy Policy / Risk Budget
→ Ready / Auto-start / Escalate
→ Authorized Executing / Verifying
→ Auto-completed / Blocked / Confirming
→ Completed / Safely Stopped / Recovery
→ Review / Learning Candidate
```

**必须始终回答**：

```text
我理解了什么；
我准备怎么做；
我正在完成哪段任务；
当前授权允许我做什么；
当前风险预算覆盖什么；
我必须在哪里升级确认；
我不会做什么；
我已经做了什么 / 没有做什么。
```

### 1.3 Delegation Center / 受托关系中心

**职责**：治理跨任务的委托关系，包括授权、风险预算、standing authorization、记忆、任务账本、审计证据与信任恢复。它不是普通设置页，也不是当前任务确认流。

**一级模块**：

```text
- 托管：当前任务 + 历史任务账本；
- 授权：可自动执行 / 必须确认 / 禁止 / 一次性授权 / standing authorization / 已撤销规则；
- 风险预算：对象 / 动作 / 频率 / 外部影响 / 期限 / 升级策略 / 违规记录；
- 记忆：已保存记忆 / 待确认学习候选 / 已拒绝记忆；
- 信任恢复：风险事件、能力降级、修复说明、重新授权入口。
```

**必须分清**：

```text
Memory ≠ Permission
Capability ≠ Permission
当前任务 ≠ 长期托管
当前上下文 ≠ 任务边界
一次确认 ≠ 长期授权
Risk budget ≠ unlimited authorization
```

## 2. 生命周期交互规则

### 2.1 快速路径与授权内自主执行

清晰、授权覆盖、可验证、在风险预算内的任务，可以把 Understanding、Plan、Boundary 压缩进行动轨迹，而不是每次都阻塞用户确认。

**允许自动推进的前提**：

```text
- 用户已经明确发起任务；
- 对象、目标环境、动作范围足够清楚；
- 自动步骤被一次性授权、standing authorization 或 risk budget policy 覆盖；
- 每一步都有内部 discipline evidence：行动记录、验证信号、边界判断；
- 结果可验证、可复盘、必要时可恢复；
- 一旦涉及未授权外部影响、不确定、多候选、权限变化、风险预算不足或验证不足，立即升级确认或停下。
```

授权内自主执行的目标是让 Janus 真正完成任务，而不是把所有步骤都推回给用户；确认、停止、接管、审计是支撑更高自主性的控制基础设施。

### 2.2 外部影响与风险预算边界

以下动作必须被一次性确认、standing authorization 或风险预算策略覆盖；否则进入 Confirming / Escalation State，不能自动越过：

```text
- 发送消息、邮件、文件；
- 评论、发布、提交表单；
- 上传、分享、修改共享权限；
- 支付、转账、审批、合同、身份认证；
- 删除、覆盖、改动重要文件；
- 保存敏感记忆或形成长期规则。
```

确认或授权必须具体到对象、内容、环境、影响、可撤销性、作用范围、期限和升级条件。外部影响边界优先于速度、完成率和演示顺畅度；已被 standing authorization 明确覆盖的例行动作可以自动执行，但必须可审计、可撤销、可升级。

### 2.3 用户控制权

用户直接在目标 App 现场编辑、发送、关闭、切换、暂停或点击“接管”，都代表用户直接操作优先。Janus 应立即暂停后续动作，不要求用户先完成显式 takeover 流程。

控制优先级：

```text
接管 > 停止 > 暂停 > 修改任务 / 修改计划 / 收紧授权 > 继续执行
```

用户停止、暂停或接管后继续执行，是风险事件。

### 2.4 Audit：done / not done / authorization used

每次完成、安全停下、失败或接管后，Janus 都必须提供 audit done / not done：

```text
已做：实际发生的动作；
未做：没有发送、没有提交、没有读取无关内容、没有保存记忆等未越权事项；
授权依据：一次性确认 / standing authorization / risk budget policy；
外部影响：无 / 已产生什么影响；
证据：关键验证信号、确认事件、用户接管事件。
```

## 3. 关键 UI 状态规格

以下状态采用统一 schema：purpose / must show / user actions / enter & exit / must not / example copy。

### 3.1 Janus Entry：Idle / 空闲

**Purpose**：保持低存在感，同时让用户知道 Janus 可随时被召唤。

**Must show**：Janus 标识、快捷键提示或轻量胶囊；可选展示是否有可恢复任务。

**User actions**：唤起输入、按住说话、打开最近任务、进入 Delegation Center。

**Enter / Exit**：无当前活跃任务进入；用户唤起或恢复任务后退出。

**Must not**：展示完整任务解释；主动开始行动；变成主应用或设置中心。

**Example copy**：

```text
你想让我完成什么？
```

### 3.2 Janus Entry：Listening / 输入与语音捕获

**Purpose**：捕获用户目标、当前对象和显式限制。

**Must show**：输入框、当前对象摘要、按住说话状态、取消方式。

**User actions**：键入目标、按住说话、松开提交、滑动/按键取消、编辑对象说明。

**Enter / Exit**：用户唤起进入；松开提交进入 Janus Surface；取消则不创建 Task。

**Must not**：把语音取消也创建任务；把入口做成搜索结果页；隐藏对象来源。

**Example copy**：

```text
当前选中：xxx.pdf
你想让我对它完成什么？
```

### 3.3 Janus Surface：Understanding State / 理解态

**Purpose**：防止高效执行错任务；结构化用户原始指令、对象、环境、限制和不确定项。

**Must show**：原始指令、理解出的目标、当前上下文、目标 App/环境、关键对象、预期结果、显式限制、不确定项。

**User actions**：正确继续、修改目标、补充说明、取消、接管。

**Enter / Exit**：任务提交后进入；清晰且授权覆盖的任务可折叠进行动轨迹；不明确、高风险或预算不足任务必须显式展示。

**Must not**：只复述“明白了”；隐藏不确定项；把推测说成事实；跳过复杂任务建模。

**Example copy**：

```text
我理解你想完成：
- 整理明天客户会所需材料；
- 更新项目文档；
- 按已授权模板发送团队例行同步；
- 客户承诺类内容先问你。

我还不确定：
- [不确定项]。
```

### 3.4 Janus Surface：Plan / Action Trace State / 计划与行动轨迹态

**Purpose**：让路径可见、可改、可审计，同时不把清晰授权任务变成多余确认。

**Must show**：分步计划、目标环境、当前上下文、关键对象、每步验证方式、停下条件、不会做什么。授权覆盖的快速路径中可默认折叠为 Action Trace。

**User actions**：开始、修改步骤、移除步骤、查看验证证据、暂停、停止、接管、取消。

**Enter / Exit**：理解完成后进入；用户开始或授权内 auto-start 后进入执行；不确定或风险升高进入 Blocked/Confirming。

**Must not**：用“我来处理”代替计划；隐藏跨 App 切换；没有停下条件；计划不可修改。

**Example copy**：

```text
我准备这样做：
1. 保持当前工作现场状态；
2. 打开或切换到目标 App；
3. 定位目标对象；
4. 完成已授权的整理 / 更新 / 发送步骤；
5. 对未授权的客户承诺内容升级确认。
```

### 3.5 Janus Surface：Autonomy Policy / Risk Budget State / 自主策略与风险预算态

**Purpose**：把能力、授权、风险预算和升级条件分开；说明 Janus 可以自动完成什么、必须问什么、不会做什么。

**Must show**：可自动动作、必须升级确认动作、禁止/不会做动作、当前自主等级、风险预算、授权来源、是否仅限本次任务。

**User actions**：继续、修改边界、收紧授权、授予一次性确认、进入 Delegation Center 查看相关规则。

**Enter / Exit**：计划形成后或执行前进入；授权内任务可嵌入 Action Trace；风险升高或预算不足时重新进入。

**Must not**：把系统权限当用户授权；把一次确认变长期规则；只讲能做不讲不会做；把风险预算做成不可审计文案。

**Example copy**：

```text
当前授权允许我自动做：
- 整理 Downloads 中最近 24 小时的会议材料；
- 更新指定项目文档；
- 按“团队例行同步”模板发送到固定群。

我需要升级确认：
- 新增收件人；
- 承诺客户交付日期；
- 修改共享权限；
- 删除或覆盖唯一文件。

我不会做：
- 读取无关文件夹；
- 静默保存新记忆；
- 超出本次风险预算继续执行。
```

### 3.6 Janus Surface：Executing / Verifying State / 执行与验证态

**Purpose**：展示 Janus 正在完成的任务，并证明每一步都是行动 → 验证 → 再行动。

**Must show**：当前步骤、下一步、最近验证结果、当前 App/窗口、是否仍在授权与风险预算范围内、暂停/停止/接管入口、可展开 Action Trace。

**User actions**：暂停、停止、接管、展开详情、修改任务、关闭 Surface 但保留胶囊锚点。

**Enter / Exit**：用户开始或授权内 auto-start 后进入；验证失败进入 Blocked/Recovery；未授权外部影响前进入 Confirming；完成后进入 Completed。

**Must not**：连续点击后一次性汇报；验证失败后猜测继续；用“处理中”遮蔽当前步骤；隐藏控制入口。

**Example copy**：

```text
当前步骤：正在更新项目文档
已验证：会议材料已归档到指定文件夹
授权依据：客户会准备 / 本次任务授权
下一步：检查是否已有明天日程
```

胶囊短文案：

```text
正在更新项目文档
[暂停] [接管]
```

### 3.7 Janus Surface：Blocked State / 阻塞态

**Purpose**：在不确定、多候选、验证不足、风险升高或预算不足时安全停下，让用户判断。安全停下是正确能力，不是失败。

**Must show**：为什么停下、当前不确定项、继续执行风险、已做、未做、用户可选路径。

**User actions**：选择对象、修改任务、授予一次性确认、手动接管、取消、进入恢复说明。

**Enter / Exit**：多候选、对象不确定、验证不足、权限/登录/验证码/支付/审批、路径偏离、用户暂停/停止/接管时进入；用户选择或修改后可回到计划/执行/确认；取消进入 Completed/Recovery。

**Must not**：为了完成率猜测；后台继续其他步骤；只说“出错了”；隐藏是否产生外部影响。

**Example copy**：

```text
我停下了，因为找到了 3 个候选。

我无法可靠判断目标对象。
继续执行可能作用到错误对象。

你可以：
[选择对象] [修改任务] [手动接管] [取消]
```

### 3.8 Janus Surface：Confirming / Escalation State / 确认与升级态

**Purpose**：在未覆盖外部影响、高责任或风险预算超界动作前形成明确授权缝。确认不是弹窗，而是授权仪式。

**Must show**：动作类型、对象、内容、目标环境、外部影响、可撤销性、为什么需要确认、本次确认是否形成规则、当前授权 / 风险预算为什么不足。

**User actions**：仅本次确认、修改内容、取消、接管；低风险重复动作可提供“创建同类 standing authorization”，但不得默认勾选。

**Enter / Exit**：执行到未覆盖外部影响边界、高风险动作、风险预算不足或用户要求确认时进入；确认后执行一次；修改回到计划/准备；取消进入完成/恢复。

**Must not**：只显示“确定/取消”；不展示对象和内容；把高风险确认做成 toast；默认勾选长期授权；把模型判断当授权依据。

**Example copy**：

```text
准备执行：[动作]

对象：[对象]
内容：[内容]
环境：[App / 空间]
影响：[外部影响]
可撤销性：[是否可撤销]

为什么需要升级确认：
[当前授权 / 风险预算未覆盖的原因]

[仅本次确认] [修改] [接管] [取消]
```

外部可见动作按钮：

```text
[执行一次] [修改内容] [取消]
```

### 3.9 Janus Surface：User Live / Takeover State / 用户现场接管态

**Purpose**：承认用户在目标 App 现场的直接操作拥有最高优先级，并让 Janus 停止后续动作。

**Must show**：已接管、已做、未做、当前停留位置、可恢复路径。

**User actions**：恢复执行、修改任务、结束任务、打开审计详情。

**Enter / Exit**：用户点击接管、直接编辑目标内容、手动发送/提交、关闭目标窗口或明显改变任务现场时进入；用户恢复前必须重新说明当前状态、授权和计划。

**Must not**：要求用户先完成 takeover 流程才停止；接管后继续排队动作；覆盖用户现场操作。

**Example copy**：

```text
你已接管。

我已经做了：
- [已完成动作]。

我没有做：
- [未发生未授权外部影响]；
- [未保存新规则]。

当前停留在：[目标 App 现场]。

你可以：
[恢复执行] [修改任务] [结束任务]
```

### 3.10 Janus Surface：Completed / Safely Stopped State / 完成与安全停下态

**Purpose**：给出可复盘的任务结果，不把完成、部分完成、安全停下和失败混为一谈。

**Must show**：最终结果、已做、未做、是否产生外部影响、使用过哪些授权、风险预算消耗、学习候选、查看历史或管理授权入口。

**User actions**：查看 Action Trace、打开 Delegation Center、保存/拒绝学习候选、恢复/修改任务、结束。

**Enter / Exit**：任务完成、取消、安全停下或用户结束后进入；若有风险事件进入 Recovery。

**Must not**：只说“完成了”；用完成掩盖部分失败；自动保存学习项；不说明外部影响或授权依据。

**Example copy**：

```text
已完成：
- 整理会议材料；
- 更新项目文档；
- 按已授权模板发送团队例行同步。

没有做：
- 没有新增收件人；
- 没有承诺客户交付日期；
- 没有修改共享权限；
- 没有保存新记忆。

授权依据：团队例行同步 standing authorization。
外部影响：已向固定项目群发送例行同步。
```

### 3.11 Janus Surface：Recovery / Trust Restoration State / 恢复与信任修复态

**Purpose**：失败、误解、风险事件或接管后恢复用户控制感，说明事实、原因、降级和恢复路径。

**Must show**：发生了什么、已经做了什么、没有做什么、为什么失败或停下、当前风险是否解除、能力是否降级、用户如何恢复。

**User actions**：手动接管、重新选择、修改任务、查看证据、接受/拒绝降级规则、进入 Delegation Center。

**Enter / Exit**：失败、路径错误、风险事件、验证不足导致停止、用户要求复盘时进入；恢复前必须重新确认状态和边界。

**Must not**：只道歉；把失败包装成成功；风险事件后继续照常自动化；不说明未发生动作。

**Example copy**：

```text
我错误地打开了不相关的联系人窗口。

我已经做了：
- 打开目标 App；
- 搜索目标名称；
- 打开了一个候选窗口。

我没有做：
- 没有输入内容；
- 没有发送或提交；
- 没有读取无关内容；
- 没有保存对象映射。

原因：
对象匹配置信不足。

后续处理：
- 本次任务已停止；
- 同名对象任务将默认要求你选择；
- 你可以手动接管或重新选择对象。
```

### 3.12 Delegation Center：Authorization / Risk Budget / Memory Governance State / 授权、风险预算与记忆治理态

**Purpose**：让用户治理长期委托关系，而不是在当前任务里被迫理解所有规则。

**Must show**：当前委托、历史任务、授权规则、风险预算、standing authorization、记忆记录、待确认学习、已撤销项、风险事件、能力降级。

**User actions**：查看任务账本、撤销授权、修改授权、调整风险预算、删除记忆、保存/忽略学习候选、查看审计证据、恢复能力。

**Enter / Exit**：用户主动打开；任务完成后查看历史；确认形成规则前；风险事件后主动出现；用户准备扩大委托范围时进入。

**Must not**：做成普通开关设置；只显示“微信权限：开”；混淆记忆、权限和风险预算；让历史只记录成功；让当前任务确认流变成长期治理页。

**Authorization record copy**：

```text
允许 Janus：
在 [环境] 中，针对 [对象]，执行 [动作]。

作用域：[本次 / 当前任务 / 特定规则 / standing authorization]
风险等级：[L0-L5]
来源：[哪次任务产生]
有效期：[时间 / 条件]
最近使用：[时间 / 任务]

[修改] [撤销]
```

**Risk budget record copy**：

```text
风险预算：
[规则名称]

允许：
- [对象 / 动作 / 频率 / 期限]

必须升级：
- [超出对象 / 新增外部影响 / 不可撤销动作]

最近消耗：
[任务 / 时间 / 动作]

[收紧预算] [暂停规则] [撤销]
```

**Memory record copy**：

```text
Janus 记住了：
[具体记忆]

来源：
[哪次任务 / 哪次确认]

用途：
[未来如何使用]

不会授予：
[不会自动执行哪些动作]

[修改] [删除]
```

## 4. 文案与信任表达模板

Janus 文案不是人格包装，也不是营销话术。它是受托关系的解释层，必须冷静、克制、明确、可验证、不邀功、不掩盖风险、不把猜测说成事实。

### 4.1 推荐句式

```text
我理解你想……
我准备这样做……
当前授权允许我……
这个动作在风险预算内……
这里需要升级确认……
我不会做……
我停下了，因为……
我已经做了……
我没有做……
```

### 4.2 避免句式

```text
放心交给我。
我全都帮你搞定。
不用管，我会处理。
我猜你应该是想……
我已经自动优化好了。
这个很简单。
马上完成。
```

### 4.3 学习候选模板

学习必须是候选，不是默认沉淀。

```text
是否记住：
[具体可学习规则]

这会用于：
[未来适用范围]

不会用于：
[不会扩展到的范围]

不会授权：
[不会因此自动执行的动作]

[记住] [仅本次] [不要记住]
```

### 4.4 Standing authorization 模板

```text
是否允许以后自动执行同类任务？

规则：
[具体规则]

允许自动做：
[对象 / 动作 / 频率 / 期限]

必须问你：
[外部影响扩大 / 新对象 / 高风险内容 / 验证不足]

你可以随时在 Delegation Center 撤销。

[创建规则] [仅本次] [取消]
```

### 4.5 文案检查清单

```text
1. 是否说明 Janus 理解了什么？
2. 是否说明 Janus 准备做什么？
3. 是否说明 Janus 不会做什么？
4. 是否说明授权依据和风险预算？
5. 是否把不确定项明确说出来？
6. 是否把确认动作的对象、内容、影响讲清楚？
7. 是否避免全能感和拟人邀功？
8. 是否避免把失败包装成成功？
9. 是否说明已做和未做？
10. 是否说明学习项需要授权？
11. 是否让用户知道如何停止、接管、撤销、复盘？
```

## 5. 代表性旅程与场景矩阵

以下场景是体验验证样本，不是产品 ontology。微信、飞书、邮件、Finder、浏览器都只是代表性目标 App / 环境；Janus 的通用对象是目标、环境、对象、动作、授权、风险预算、验证和结果。

### 5.1 旅程一：授权内多步目标完成

**场景**：用户在任意 App 中长按 Janus Entry，说：

```text
帮我准备明天客户会：整理下载目录里的最新材料，更新项目文档，给团队发一条例行同步，日程如果还没建就创建一个。例行同步可以按我之前授权的模板发送；客户承诺类内容需要先问我。
```

**流程**：

```text
1. 用户按住 Janus Entry，开始语音捕获；
2. 松开即提交，Janus 创建 Task；取消则不创建 Task；
3. Janus Surface 结构化目标、约束、授权线索和风险预算；
4. Janus 检查 standing authorization：团队例行同步模板、固定项目群、允许频率；
5. Janus 自动整理材料、更新文档、检查日程、发送授权覆盖的例行同步；
6. 遇到客户承诺、收件人变化、权限修改或验证不足，进入 Escalation State；
7. 结束后展示 done / not done / authorization used / risk budget audit 和学习候选。
```

**关键规格**：

```text
- 完成是默认志向；
- 授权内外部可见例行动作可以自动执行；
- 客户承诺、权限变化和预算超界必须升级；
- Action Trace 中保留内部 discipline evidence；
- 任务结束必须说明已发送什么、没有承诺什么、没有读取/删除/保存什么。
```

### 5.2 旅程二：长按语音快速路径，跨 App 创建可确认草稿

**场景**：用户在任意 App 中长按 Janus Entry，说：

```text
打开微信给张三写条消息：我十分钟后到。发送前让我确认。
```

**流程**：

```text
1. 用户按住 Janus Entry，开始语音捕获；
2. 松开即提交，Janus 创建 Task；取消则不创建 Task；
3. Janus 捕获当前 App 作为上下文线索，但目标环境是微信；
4. 任务清晰、以草稿准备为主，Understanding / Plan / Boundary 折叠进 Action Trace；
5. Janus 自动打开或切换目标 App、搜索联系人、输入草稿；
6. 发送前进入 Confirming State；
7. 用户发送一次、修改内容、取消或接管；
8. 结束后展示 done / not done audit 和学习候选。
```

**关键规格**：

```text
- 当前窗口不是任务边界；
- 准备动作可自动推进；
- 用户已要求发送前确认，因此发送必须确认；
- 任务结束必须说明没有未经确认发送 / 没有读取无关内容 / 没有保存映射。
```

### 5.3 旅程三：当前对象入口，跨 App 准备文件或文档草稿

**场景**：用户在 Finder 选中 PDF，或在浏览器打开资料页，然后唤起 Janus：

```text
把这个 PDF 发给李四，发送前确认。
```

或：

```text
把这页整理成飞书草稿，先不要发布或分享。
```

**流程**：

```text
1. Janus Entry 明确当前对象来源：选中文件 / 当前网页可见内容；
2. Janus Surface 说明目标环境、对象、可自动准备动作和必须确认动作；
3. Janus 自动执行准备：打开目标 App、搜索对象、创建未共享草稿、预选附件或整理内容；
4. 上传、发送、发布、分享、修改权限前必须被授权覆盖，否则 Confirming；
5. 完成后展示对象来源、已做、未做、外部影响、是否产生学习候选。
```

**确认卡样例**：

```text
准备发送文件

对象：李四 / 目标联系人
文件：xxx.pdf
来源：本地 Finder 当前选中文件
影响：对方将收到该文件
可撤销性：发送后可能无法撤回

为什么需要确认：
发送文件是外部可见动作，且当前没有 standing authorization 覆盖。

[仅本次发送] [更换联系人] [取消]
```

### 5.4 场景矩阵：安全停下、接管、恢复、治理

| 场景 | 正确状态 | 必须展示 | 用户动作 | 禁止行为 |
|---|---|---|---|---|
| 多候选对象 | Blocked | 找到几个候选、为什么无法判断、继续风险、已做/未做 | 选择对象、修改任务、接管、取消 | 猜测默认候选、继续后台执行 |
| Standing authorization 覆盖例行同步 | Executing / Completed | 授权来源、对象、内容、外部影响、风险预算消耗 | 查看、撤销、修改规则 | 每步打断；隐藏已发送事实 |
| 风险预算不足 | Confirming / Escalation | 哪项预算不足、继续影响、已做/未做 | 仅本次确认、收紧/扩大授权、接管、取消 | 把预算不足当普通确认跳过 |
| 用户直接编辑目标 App | User Live / Takeover | 已接管、已做、未做、当前停留位置 | 恢复、修改、结束 | 要求用户先确认接管才停止 |
| 用户点击停止 | Safely Stopped | 停止原因、已做、未做、外部影响 | 查看复盘、恢复、结束 | 停止后继续执行排队动作 |
| 验证信号不足 | Blocked / Recovery | 哪个验证不足、继续风险、可恢复路径 | 手动选择、重试前确认、接管 | 猜测继续、把未知说成已验证 |
| 误打开对象但未输入/发送 | Recovery | 发生了什么、已做、未做、原因、能力降级 | 接管、重新选择、查看证据 | 只道歉、不降级、包装成成功 |
| 用户想撤销规则 | Delegation Center | 规则对象、动作、作用域、来源、最近使用 | 修改、撤销、查看历史 | 只提供总开关、不说明影响 |
| 学习候选 | Completed / Delegation Center | 记住什么、用途、不会用于什么、来源 | 记住、仅本次、不要记住 | 默认保存、跨 App 扩张 |

## 6. 规格追踪矩阵

| Canonical concept | Experience mechanism | Primary state | Evidence |
|---|---|---|---|
| full-capability entrusted Agent | Entry 发起委托，Surface 承载生命周期，Delegation Center 治理长期关系 | 三 surfaces | 用户知道是在委托行动，不是聊天/搜索 |
| 授权内自主完成 | Autonomy Policy / Risk Budget，authorized auto-start，Action Trace 折叠理解/计划/边界 | Executing / Completed | 任务被完成，且授权依据可见 |
| press-and-hold fast path | 按住捕获、松开提交、取消无 Task | Entry Listening | Task 创建只发生在提交后 |
| external-impact policy | 外部可见动作由 one-time confirmation / standing authorization / risk budget 覆盖 | Confirming / Completed | 对象、内容、影响、可撤销性、授权来源 |
| sovereignty | 目标、判断、身份、责任保留给用户 | 全状态 | 可修改、确认、接管、复盘 |
| permission / memory / risk budget boundary | 授权规则、风险预算与记忆记录分开治理 | Delegation Center | 授权、预算和记忆记录独立 |
| evidence verification | 行动 → 验证 → 再行动 | Executing / Action Trace | 每步验证信号可展开 |
| stop / pause / takeover / modify / recover / revoke / review | 控制动作贯穿胶囊、Surface、Delegation Center | 全状态 | 用户能暂停、停止、接管、撤销、查看历史 |
| audit done / not done / authorization used | 完成、停下、失败都展示已做/未做/外部影响/授权依据 | Completed / Recovery | 用户知道产生了什么、没有产生什么、基于什么授权 |

## 7. 最小设计检查

任何 Janus 原型或交互改动上线前，只做这一组检查：

```text
对象：Janus Entry / Janus Surface / Delegation Center / 目标 App 现场 / 审计历史
状态：Idle / Active / User Live / Confirming / Completed / Stopped / Managed
职责：这次元素只解决什么产品问题
非职责：这次明确不承载什么
```

并确认：

```text
1. 是否仍然只有三种 surfaces？
2. 是否让 Janus 像全能受托 Agent，而不是聊天助手、任务管理器或设置面板？
3. 是否保护用户的目的权、判断权、身份权和责任？
4. 是否让授权范围内的任务被完成，而不是停留在不必要准备态？
5. 外部影响是否被一次性确认、standing authorization 或 risk budget policy 覆盖？
6. 超出授权或风险预算时是否升级确认或停下？
7. 是否让用户随时停止、暂停、接管、修改、恢复、撤销、复盘？
8. 是否把记忆、权限和风险预算分开治理？
9. 是否展示内部 discipline evidence 和 audit done / not done / authorization used？
```

如果一个设计只能证明 Janus 能自动完成任务，却不能证明用户仍保留主权、边界、控制和追溯，它不是合格的 Janus 体验设计。如果一个设计只能证明 Janus 足够谨慎，却让已授权任务无法完成，它也不是合格的 Janus 体验设计。
