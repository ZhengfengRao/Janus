## 1. 产品一句话定义

> Janus 是把现有软件转化为可调用能力节点的通用受托行动层，让用户用一句目标快速完成跨 App 机械路径。

更完整地说：

> Janus 是 macOS 上的通用受托行动层。用户可以在任意数字工作现场唤起 Janus，把跨软件的重复界面劳动委托给它；Janus 自动处理打开、切换、查找、整理、创建草稿等机械路径，把用户尽快带到可检查、可修改、可确认的结果，并在真正影响外部世界或用户责任的位置停下。

Janus 不是普通 AI 助手，不是桌面聊天框，不是单 App 插件，也不是试图替代微信、飞书、邮箱、浏览器或文件系统的超级 App。它位于用户和软件之间，把现有软件转化为用户意图可以调用的能力节点。

```text
用户 → Janus → 各种软件
```

最高权力归属不变：

```text
目标由人给出；
路径由 Agent 处理；
关键动作由人确认；
过程必须可见；
权力必须可撤回。
```

## 2. 产品要解决的真实问题

表层问题是用户每天在多个软件之间重复打开、搜索、切换、复制、粘贴、整理、创建草稿、上传下载和记忆流程。

深层问题是：

> 现代软件把人变成了界面劳动者。

Janus 的正当性不是“替代人”，而是：

> 把机械性还给机器，把主体性还给人。

产品问题定义：

```text
如何让用户快速把重复的跨软件行动委托给 Janus，减少界面劳动和流程记忆，同时在真正影响用户主权、身份、责任或外部世界的边界保留确认、接管、验证和复盘。
```

这要求 Janus 先交付高速、低风险、跨 App 的机械路径替代价值，再通过授权、可见性、中断、确认、验证、复盘、记忆治理和信任恢复，让委托长期可信。

## 3. 用户与使用场景

Janus 面向被软件流程消耗的 macOS 用户，早期核心用户是高频跨软件工作者：知识工作者、沟通密集型用户、项目管理与协作用户、创作者与研究者、普通大众用户。

Janus 不按 App 划分用户，而按委托成熟度划分：

| 用户阶段 | 心智 | 典型需求 | 产品重点 |
|---|---|---|---|
| 初次体验者 | 想知道它能不能帮我 | 打开 App、找文件、创建草稿 | 快速入口、低风险任务、明确边界 |
| 低风险委托者 | 愿意让它做机械步骤 | 搜索、切换、填写草稿、整理信息 | Janus Surface、单步验证、可接管 |
| 稳定协作者 | 愿意给有限授权 | 固定流程、重复路径、常用对象 | 授权规则、任务历史、恢复能力 |
| 深度治理者 | 关心长期信任 | 管理权限、记忆、审计、能力边界 | Delegation Center、信任恢复 |

核心 JTBD：

```text
当我有一个需要跨软件完成的数字目标时，
我希望只表达目标和边界，
让系统快速处理机械路径，
把我带到可检查、可修改、可确认的结果，
这样我可以减少界面劳动，同时在关键风险点保持控制权。
```

## 4. 产品原则

| 原则 | 产品规则 |
|---|---|
| 用户主权 | Janus 必须保护目的主权、判断主权、身份主权、责任主权。 |
| 能力不是权力 | Capability ≠ Permission ≠ Necessity ≠ Executability。能打开、点击、输入、读取，不等于有权这样做。 |
| 当前上下文是线索，不是边界 | 当前 App / Window / 选中对象可帮助理解任务，但任务边界由用户目标、授权、风险和验证共同决定。 |
| 单步行动，单步验证 | Janus 的内部纪律是 `行动 → 验证 → 再行动`；证据验证不能被模型置信度替代。 |
| 安全停下不是失败 | 遇到不确定、高风险、验证不足、用户中断或边界冲突时，正确行为是 Safely Stopped。 |
| Learning Candidate ≠ Memory | 可发现学习候选，但不能静默保存长期记忆。 |
| Memory ≠ Permission | 保存记忆不能扩大行动权限；授权行动不能自动保存记忆。 |
| 一次确认 ≠ 长期授权 | 单次确认只对当前动作或当前任务有效，长期授权必须在 Delegation Center 明确治理。 |
| 外部影响边界 | 发送、提交、上传、发布、审批、支付、权限变更等外部影响动作必须停下确认。 |
| 低风险自动化允许 | 打开、切换、搜索、整理、生成草稿等低风险动作可自动执行，但必须可见、可中断、可验证、可复盘。 |

## 5. 产品总体结构

Janus 只有三个 canonical 产品表面：

```text
Janus Entry / Janus 入口
Janus Surface / Janus 主行动面
Delegation Center / 受托关系中心
```

| 表面 | 解决的问题 | 不承载 |
|---|---|---|
| Janus Entry | 如何随时把一个目标交给 Janus，并在任务中停止、恢复或聚焦当前任务 | 完整任务解释、长期治理、复杂设置 |
| Janus Surface | 如何完成一次受托任务：理解、计划、权限/风险、执行、验证、确认、停下、复盘 | 跨任务权限/记忆治理 |
| Delegation Center | 如何长期治理托管任务、权限、记忆、审计和信任恢复 | 当前任务的主要确认流 |

### 5.1 Janus Entry

Janus Entry 是用户在任意 macOS 工作现场发起或恢复 Janus 的入口。它必须：

- 随时可达，但不随时观察；
- 低存在感，但任务中可见；
- 能发起任务，也能停止、暂停、恢复或聚焦当前任务；
- 可基于当前上下文，但不被当前上下文限制；
- 采用单一任务胶囊，支持可编辑输入、提交和长按语音。

长按语音是最高频 fast path：用户长按 Janus Entry 或语音按钮开始采集，松开结束并提交 Intent；Janus Surface 承接任务。对象明确、风险较低、以准备/草稿/整理为主的任务，可直接推进到可检查结果或等待确认状态。理解、计划、权限/风险判断、步骤验证和审计仍必须存在，只是默认折叠进行动轨迹。外部影响动作仍必须确认。

### 5.2 Janus Surface

Janus Surface 是一次受托任务的核心协作界面，是同一受托行动界面在不同生命周期中的状态容器。

它承载：目标理解、Plan 或 Action Trace、权限与风险、执行状态、验证结果、阻塞与确认、中断与接管、完成复盘、学习候选。

核心叙事：

```text
我理解了什么；
我准备怎么做；
我不会做什么；
我正在做什么；
我为什么停下；
我已经做了什么；
我没有做什么。
```

### 5.3 Delegation Center

Delegation Center 是治理 Janus 行动权的空间，不是传统设置页，也不是长期并行任务后台。

它回答：我把什么交给了 Janus、Janus 可以自动做什么、Janus 必须问我什么、Janus 记住了什么、Janus 曾经做过什么、Janus 哪里失败过以及如何恢复信任。

一级模块：

1. **托管**：当前任务 + 可展开历史任务的串行账本；
2. **权限**：跨任务授权规则治理，覆盖自动执行、发送前确认、禁止执行、一次性授权和撤销；
3. **记忆**：跨任务记忆治理，覆盖已保存偏好、联系人线索、App 习惯和待确认候选。

审计、信任恢复和能力降级作为任务行、权限行和记忆行背后的可展开证据与治理能力，不堆叠为更多 canonical 产品表面。

## 6. 核心任务生命周期设计

完整生命周期：

```text
Intent Capture
→ Understanding
→ Planning
→ Permission & Risk Check
→ Ready / Auto-start
→ Executing
→ Verifying
→ Blocked / Confirming
→ Completed / Safely Stopped / Failed
→ Review & Learning Candidate
```

面向用户可压缩为：

```text
表达目标 → 理解目标 → 展示计划 → 声明边界 → 执行与验证 → 确认或停下 → 复盘与学习
```

| 阶段 | 产品规则 |
|---|---|
| 表达目标 | 捕获原始指令、入口、当前环境、目标环境、目标对象、显式限制、外部影响和确认偏好。 |
| 理解目标 | 形成可审查理解；低风险清晰任务可折叠展示，但内部纪律不能省略。 |
| Plan / Action Trace | 计划必须存在于任务模型和审计证据中；清晰低风险链路可不作为执行前阻塞步骤。 |
| 权限与风险 | 说明“可以自动做 / 必须停下 / 不会做”。 |
| 执行与验证 | 每个 Step 执行后进入 Verifying；没有验证信号，不继续自动执行。 |
| 阻塞、确认与接管 | 多候选、对象不确定、外部影响、删除/覆盖/上传/权限修改、登录/验证码/支付/审批、用户暂停/停止/接管、验证不足、路径偏离都必须停下。 |
| 完成、失败与复盘 | 记录已做、未做、是否产生外部影响；Safely Stopped、Failed、Completed 必须区分。 |

用户对当前任务始终拥有停止、暂停、接管、修改、恢复、撤销、复盘权。

## 7. 权限、风险与确认产品规则

### 7.1 风险等级

| 等级 | 名称 | 示例 | 产品策略 |
|---|---|---|---|
| L0 | 观察 | 识别当前窗口、读取选中对象 | 显示采集范围，可关闭 |
| L1 | 导航 | 打开 App、切换窗口、搜索 | 可自动执行，需可见 |
| L2 | 准备 | 输入草稿、预选文件、生成内容 | 可自动执行，但需验证 |
| L3 | 本地状态变化 | 保存文件、重命名、移动 | 通常需确认或明确授权 |
| L4 | 外部可见动作 | 发送消息、邮件、评论、提交表单 | 必须强确认 |
| L5 | 高风险代理动作 | 支付、审批、权限变更、不可逆操作 | 默认禁止或多重确认 |

L4/L5 是 hard stop；除非用户明确确认并符合授权边界，否则不得继续。

### 7.2 R 类风险事件

R 类风险事件是一票否决事件，必须拦截或进入人工确认：未经确认发送/提交/发布/审批；用户停止、暂停或接管后仍继续执行；静默保存敏感记忆；一次确认泛化为长期授权；用模型置信度替代验证信号；任务外持续观察；把 Recovery、Blocked、Safely Stopped 伪装为 Completed。

### 7.3 授权表达

授权类型：一次性授权、条件授权、长期授权、禁止规则。

授权必须具体到 App、对象、动作、风险等级和有效范围。例如：

```text
允许 Janus 在飞书中自动搜索并打开你指定的文档；
不允许 Janus 自动分享、删除、修改权限或发送消息。
```

### 7.4 确认卡

高风险确认卡必须包含：动作类型、目标对象、目标环境、即将产生的外部影响、是否可撤销、Janus 已经做了什么、Janus 还没有做什么、用户可选项（确认、修改、接管、取消）。

## 8. 记忆、学习与个性化产品规则

| 规则 | 说明 |
|---|---|
| 学习不是默认发生 | Janus 可以识别 Learning Candidate，但必须由用户决定是否保存。 |
| 记忆必须可治理 | Delegation Center 提供查看、来源、编辑、撤销、作用范围和使用历史。 |
| 记忆类型有限 | 用户偏好、对象映射、环境知识、流程偏好、禁止偏好。 |
| 记忆不产生权限 | 记住“张三是谁”不等于允许自动给张三发消息。 |
| 权限不产生记忆 | 允许本次发送前创建草稿，不等于保存联系人映射或组织信息。 |
| 候选项不等于事实 | Learning Candidate 在用户确认前只能作为本次任务线索。 |

记忆提示必须提供至少三个选择：仅本次使用、记住、不要再提示。

## 9. 核心界面摘要

详细状态、布局、文案和组件规范属于 `janus-product-experience-design.md`。本文只保留产品结构摘要。

### 9.1 Janus Entry 摘要

默认形态是单一任务胶囊：

```text
[J]  你想让 Janus 做什么？  [按住说话] [↵]
```

任务中可变为状态胶囊或进入 Janus Surface 执行态，支持暂停、停止、接管、恢复、查看行动轨迹。

### 9.2 Janus Surface 摘要

Janus Surface 动态呈现目标摘要、当前理解、Plan / Action Trace、权限与风险、当前步骤、验证结果、停下原因或确认卡、时间线、学习候选。不同阶段动态显示，不应一次性堆满。

### 9.3 Delegation Center 摘要

```text
Delegation Center
├── 托管：当前任务 + 历史任务
├── 权限：自动执行 / 发送前确认 / 禁止执行 / 一次性授权 / 已撤销授权
└── 记忆：已保存偏好 / 联系人线索 / App 习惯 / 待确认学习项 / 已删除或已忽略记忆
```

串行托管是前提：当前任务只能有一个；历史任务用于查看和复盘，不用于恢复长期并行委托。

详细 journey、状态和 copy 属于 `janus-product-experience-design.md`。本文只保留验证产品模型的代表性场景。

## 11. 产品文案与信任表达规范

| 类别 | 规则 |
|---|---|
| 文案原则 | 明确而不拟人过度；解释边界而不制造恐惧；承认不确定而不显得无能；汇报行动而不掩盖未做事项；请求确认而不转移责任。 |
| 推荐句式 | “我理解你想……”“我不确定……”“我可以自动做……”“我必须停下……”“我不会做……”“已验证……”“我已经做了……”“我没有做……”。 |
| 禁止句式 | “放心交给我”但不说明边界；“我认为可以发送”替代用户确认；“以后我都这样做”但没有授权范围；“我记住了”但没有用户授权；把安全停下说成失败或完成。 |

## 12. 产品与技术运行时映射

| 产品机制 | 技术对象 / 模块 | 产品要求 |
|---|---|---|
| 用户输入目标 | Intent | 保留原始表达和显式限制 |
| 一次委托任务 | Task | 所有行动必须绑定 Task |
| 当前与目标环境 | Context / EnvironmentRef | 当前上下文是线索，不是边界 |
| 行动计划 | Plan | 可解释、可修改、可审计 |
| 单步动作 | Step / Action | Step 是最小可执行单位 |
| 授权边界 | PermissionGrant / DelegationRule | 授权可查看、可撤销 |
| 风险判断 | Risk / PolicyDecision | L4/L5 和 R 类事件强拦截 |
| 确认卡 | ConfirmationPayload | 外部影响前必须确认 |
| 执行状态 | ExecutableStep / Task State | 执行后必须验证 |
| 验证结果 | VerificationRequirement / VerificationEvent | 模型置信度不是验证信号 |
| 中断接管 | InterruptToken | 用户中断最高优先级 |
| 审计时间线 | AuditEvent / Timeline | 记录已做和未做 |
| 学习候选 | LearningCandidate | 不自动保存为 Memory |
| 长期记忆 | Memory | 明确授权、可撤销、可审计 |

## 13. 研发衔接与产品验证门

研发路线遵循：

```text
Evidence-first Native Runtime
证据优先的本地桌面运行时路线
```

顺序：先建立 Task / Step / Permission / Risk / Verification / Audit 运行纪律，再接入 macOS 控制能力，再接入模型理解和规划能力，最后扩展 App 能力、记忆能力、并发能力和第三方扩展能力。

| Gate | 名称 | 产品通过标准 |
|---|---|---|
| Gate 0 | 总纲一致性门 | 功能能追溯到通用受托行动层，不破坏用户主权 |
| Gate 1 | Runtime 骨架门 | 产品界面能表达 Task、Step、Permission、Risk、Verification、Audit |
| Gate 2 | 低风险单步执行门 | 低风险动作可见、可中断、可验证 |
| Gate 3 | 跨 App 草稿闭环门 | 能从任意上下文进入目标 App 创建草稿，并在外部影响前停下 |
| Gate 4 | 信任治理门 | 授权、记忆、历史、审计、恢复可由用户治理 |
| Gate 5 | 能力扩展门 | 新 App / 新能力不绕过既有权限、风险和验证纪律 |

派生 PRD 必须说明：用户问题、生命周期阶段、风险等级、授权类型、验证信号、审计内容、安全停下条件、不做什么、与三大产品表面的关系、对 Gate 0-5 的影响。

## 14. 产品成功指标

Janus 的成功首先看是否显著减少界面劳动、缩短从意图到可检查结果的路径；自动化完成率、确认、停下和复盘都是支撑高速委托可信持续的指标。

| 指标 | 含义 |
|---|---|
| 界面劳动减少率 | 用户是否少切换、少查找、少复制粘贴、少记流程 |
| 可准备结果到达时间 | 从表达目标到可检查草稿 / 结果 / 等待确认状态的时间 |
| 低风险自动路径完成率 | 清晰低风险任务是否能自动完成机械路径并停在结果处 |
| 重复流程复用率 | 用户是否愿意把同类低风险任务交给 Janus 重复处理 |
| 外部影响误触发率 | 未确认发送、提交、删除等必须接近 0 |
| 用户接管成功率 | 用户能否随时接管并理解状态 |
| 验证信号覆盖率 | Step 是否有可靠验证依据 |
| 复盘可理解度 | 用户能否理解已做和未做 |
| 授权撤销成功率 | 撤销后是否立即生效 |
| 记忆误保存率 | 未授权记忆保存必须为 0 |
| 信任恢复率 | 风险事件后用户是否能恢复使用 |

反指标：自动执行步数越多越好、覆盖 App 越多越好、模型回答越自然越好、用户确认越少越好、后台主动性越强越好。若这些指标破坏用户主权、授权边界、可见性、验证或复盘，应降级。

## 15. 产品反模式清单

| 反模式 | 禁止原因 |
|---|---|
| 聊天框化 | 把 Janus 做成只会回答问题的桌面 Chatbot。 |
| 启动器化 | 把 Janus 做成只负责打开 App 或搜索入口的 launcher。 |
| 插件化 | 把 Janus 降级为单 App 插件，失去通用受托行动层。 |
| 超级 App 化 | 试图替代微信、飞书、邮箱、浏览器或文件系统。 |
| 脚本化 | 把能力固化为逐 App、逐场景脚本。 |
| 黑箱自动化 | 执行过程不可见、不可中断、不可复盘。 |
| 效率至上 | 为了少确认而越过风险边界。 |
| 拟人越权 | 让 Janus 像用户本人一样承诺、拒绝、道歉或发送。 |
| 后台监控 | 把 Janus Entry 误做成长期观察系统。 |
| 静默学习 | 未经授权保存联系人、路径、偏好、组织信息。 |
| 一次确认泛化 | 把单次授权推导为长期权限。 |
| 模型置信替代验证 | 用“AI 觉得成功”替代证据。 |
| 完成伪装 | 把 Recovery、Blocked、Safely Stopped 说成 Completed。 |

## 17. 最终产品判断

Janus 的完整产品形态不是：

```text
一个会控制电脑的 AI；
一个跨 App 自动化脚本集合；
一个桌面聊天助手；
一个替代所有软件的超级 App。
```

Janus 的完整产品形态是：

```text
一个以用户目标为起点，
以任务生命周期为协作界面，
以权限、风险、验证和审计为运行纪律，
以 Delegation Center 管理长期信任，
在 macOS 软件世界中替人承担机械路径、但不夺取人的主权的通用受托行动层。
```

这份产品设计的最高标准不是让 Janus 显得无所不能，而是让它在能力增长时仍然知道边界；在执行任务时仍然可见、可停、可查；在产生外部影响前仍然尊重用户确认；在学习用户习惯时仍然接受治理；在失败和不确定时仍然安全停下。
